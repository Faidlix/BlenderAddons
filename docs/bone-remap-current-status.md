## 原始待辦與後續驗收

### 使用者新增需求（2026-10-07，原始驗收規格；目前狀態見上節）

- 動畫清單「設為原地動畫」左側的分隔線，拖曳時只調整其相鄰欄位；不得連帶改變右側「複製對稱動畫」欄位寬度或位置。標題與下方按鈕仍須對齊。
- 目前所有欄寬拖曳反應過於靈敏；降低位移增益，讓按住拖曳可細緻控制，放開即結束。修改時檢查動畫清單與骨骼對應清單的分隔線。
- 動畫清單下方兩種選項的 `O`／`X` 按鈕，改顯示「啟用」／「未啟用」；按鈕預留「未啟用」的固定寬度，使切換狀態時欄寬與對齊不跳動。
- 骨骼對應表中，拖曳「Target 骨骼」左側紅框控制桿不得改變「IK 設定」欄寬；在 Target 骨骼與 IK 設定之間補一個可獨立拖曳的控制桿。「IK 設定」標題要與下方「設定 IK」按鈕欄對齊，兩個控制桿各自只調整其對應欄位。
- 「設定 IK」按鈕留在骨骼對應表的 IK 欄，但完整 IK 編輯器不得固定展開在屬性欄（使用者截圖所示位置）；按鈕應開啟可操作的彈出視窗，取消／確認／刪除後依既定行為關閉視窗。此項是對前述「IK 設定欄」的補充，不是要求移走表格內的按鈕。
- Pole「調整長度」採單一的目標角色前後軸、有正負號的位移：`0` 位於對應上一節骨架的尾端／關節端點（手為手肘、腳為膝蓋），正值往角色正前方、負值往正後方。預設長度依該肢體的彎曲方向選 `+1` 或 `-1`；使用者可跨過 `0` 改變方向。手部先前圖示要求朝後、腳部此圖紅線要求朝前，但不可寫死「手必後、腳必前」，應以實際彎曲方向決定。不得沿手臂左右方向或把螢幕紅線硬編碼成世界座標軸；切換 Target 前方軸／預覽後也須維持同一語意。此需求取代先前「增加長度一律往後」的描述，尚未實作與驗證。
- 「使用 Pole」必須控制實際 Pole 骨架與其顯示的生命週期：關閉時移除此外掛建立的該 Pole 控制骨／視覺，並清除 IK 約束對它的參照；重新開啟時重新建立該 Pole 控制骨／視覺並接回約束。不能只切換約束而讓未使用的 Pole 方框留在 3D View。實作時檢查重複切換不產生孤立控制骨、形狀物件或錯誤參照；既有動畫 Key 的處理須一併驗證。
- Pole 動畫轉錄規劃（僅記錄，待實做）：目前 `retarget.py::_ik_pole_position` 由 Target 暫存 FK 的彎曲向量直接估位置，之後只給 Pole 下 Key，沒有把 IK 求解後的肘／膝姿勢與原動畫逐幀比較。改為每個取樣幀先在來源骨架的已評估姿勢抓取上節、關節、末端的世界位置與旋轉，再透過既有對位／縮放轉換到 Target 空間；同時保留 Target 約束暫停時的 FK 期望姿勢。由髖／肩到末端的方向投影出關節彎曲平面，結合來源關節旋轉、前一幀 Pole 方向與使用者的前後向有號長度，求出 Pole 初值。近乎伸直或彎曲平面不穩定時沿用上一幀／校準姿勢，避免 180° 翻面。
- 每幀啟用 IK 後，實際評估控制器與 Pole 對末端位置／旋轉、肘／膝位置與彎曲方向的影響；必要時只調整 Pole 軌跡與 IK 控制器姿勢，重新求解直到誤差降低或達到安全迭代上限，再寫入控制器與 Pole Key。`pole_angle` 先按每條鏈的參考姿勢校準，不用來源骨骼名稱或固定世界軸猜測；不能僅因 Key／FCurve 存在就判定還原成功。若來源鏈不完整或無可用彎曲方向，採明確回退並記錄原因，不破壞原動畫。
- 驗證規劃：同一角色與 Run.fbx、Walk.fbx 及含手部動作的片段，在無 IK 的轉錄結果、IK 求解前的期望 FK、IK 求解後姿勢之間逐幀比較肩／髖、肘／膝、手／腳的世界座標、末端旋轉、彎曲平面角、Root 位移與時間連續性；測試左右手腳、直肢、快速旋轉、不同來源／Target 前方軸及 Pole 長度正／零／負。前景截圖需同時看見角色網格、來源骨架、目標骨架和影格。0 長度在 UI 仍位於關節端點，求解時需特別處理退化方向，不可產生跳動或 NaN。這些比較尚未執行，允許的姿勢誤差門檻須以角色尺度與無 IK 基線訂定。
- IK「關聯骨頭數」不得為 `0`；屬性下限與建立／更新 IK 約束時的驗證均應至少為 `1`，並處理既有檔案可能已存 `0` 的情況。預設值仍維持 `2`，除非使用者另行要求。
