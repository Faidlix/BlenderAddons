## 3. 刪除動畫檔案後更新骨骼對應

- 刪除任一動畫檔案後，骨骼對應區立即重新選擇資料來源。
- 以刪除後清單中最上方的動畫檔案為基準，重新檢查是否存在可沿用的骨架映射。
- 不得繼續引用已刪除檔案的沿用映射、Action 或清單索引。

### 驗收

- 刪除目前映射來源後不出現空參照、錯誤選項或舊檔名。
- 骨骼對應自動反映最上方剩餘檔案可用的獨立／沿用映射狀態。

## 4. T-Pose、預覽與自動配骨架流程

- 目前的預覽區再拆成兩個按鈕：左側 `T-Pose`、右側保留現在的「預覽」。
- `T-Pose` 進入骨架調整視圖，將骨架呈現為便於映射的 T 字姿勢，視覺目的類似進入骨架編輯畫面。
- 「骨架縮放對位」功能併入「自動配骨架」。
- 合併後移除原本獨立的「骨架縮放對位」按鈕。
- 進入預覽前必須保存 Target 原本的 Action；取消預覽時完整還原。
- 若 Target 原本沒有 Action，取消預覽後必須恢復為 `None`，不能殘留預覽 Action。

### 驗收

- T-Pose 與動畫預覽可獨立切換，不互相混淆。
- 自動配骨架完成時同時處理必要的骨架縮放對位。
- 預覽取消後，Target 的 Action 與進入預覽前完全一致。

## 5. 骨骼對應欄位對齊

- 修正圖 5 的欄位標題、項目內容與名稱輸入框水平位置。
- `來源骨骼`、`Target 骨骼`、`IK 設定`、軸向狀態及調整軸向控制，需與各自欄內容使用同一欄起點與寬度。

### 驗收

- 標題文字中心或左緣與下方資料欄一致，不再出現逐欄偏移。
- 選取列與一般列使用相同欄位配置。

## 6. 手指與腳趾群組收合時保留捲動位置

- 按下手／腳群組的收合按鈕後，清單不可跳回最上方。
- 保留目前捲軸位置與目前可見的父骨頭位置，只更新該父骨頭以下被收合或展開的子項目。
- 收合後由後續骨頭補上空出的可視區域；父骨頭以上的畫面位置不動。

### 驗收

- 在清單中段或底部收合手指／腳趾時，使用者視線仍停留在同一父骨頭附近。
- 展開時同樣不得無條件重設清單捲動位置。

## 7. 手指與腳趾縮排

- 手指及腳趾子項目的縮排減少至圖 7 紅線位置。
- Source 與 Target 欄同步使用相同縮排量。
- 僅調整名稱與對應欄位的水平縮排，不移動 IK 按鈕及後續狀態欄。

### 驗收

- 子項目仍能辨識階層，但不再浪費過多橫向空間。
- 長骨頭名稱獲得更多可用顯示寬度，且所有後續操作欄維持原位。

## 8. IK 設定區固定清單高度並保留捲動位置

- 按下「設定 IK」時，不增加骨骼清單的整體可視高度；IK 設定內容插入目前選取骨頭的下一列，原本位於其下方的骨頭依序往下移。
- 右側清單捲軸維持完整高度與正常捲動範圍，不可為了讓選取骨頭置頂而隱藏其上方的骨頭。
- 離開 IK 設定畫面後，不要跳回進入設定前的位置，也不要重設到清單頂端；直接從離開時的目前位置繼續上下捲動。
- 「Cancel」、「OK」與「刪除 IK」都套用相同的捲動位置保留規則。

### 驗收

- 展開 IK 設定前後，骨骼清單外框與右側捲軸高度不變。
- 展開時僅重新排列選取骨頭以下的可見內容；關閉後可從當下位置連續捲動，畫面不彈回。
- 選取骨頭上方的項目仍可透過正常捲動查看，未被清單篩選邏輯移除。

## 9. IK Custom Shape 的 Outliner 顯示與渲染狀態

- `__FBR_IK_Shapes__` 集合及 `FBR_IK_SHAPE_BOX`、`FBR_IK_SHAPE_CIRCLE`、`FBR_IK_SHAPE_SPHERE` 是 IK 骨頭預覽使用的輔助 Shape。
- 目前骨頭上的球形／Box 等 Custom Shape 預覽看不到，是因為這些輔助物件在 Outliner 被設為隱藏顯示。
- 後續實作需分開處理視窗顯示與最終渲染：輔助 Shape 必須能在 3D Viewport 作為骨頭 Custom Shape 正常顯示，但不可出現在最終渲染結果中。
- 建立或重用該集合與物件時，都要恢復／維持正確的 Outliner 可見性狀態，避免舊檔案中的隱藏旗標讓 IK 預覽再次消失。
- 按下「刪除 IK」並確認後，必須同步移除該骨頭使用的 Custom Shape、控制骨及相關 IK 設定，不可在骨頭或場景中留下球形、Box、Circle 等殘留形狀。

### 驗收

- 設定 IK 並選擇球形、Box 或 Circle 後，對應形狀會顯示在指定骨頭上。
- 輔助 Shape 不會作為一般模型出現在最終渲染中。
- 關閉並重新開啟檔案，或再次進入 IK 設定時，預覽仍可正常顯示。
- 刪除 IK 後立刻離開設定畫面，該骨頭的預覽形狀與 IK／控制骨關聯全部消失；其他骨頭仍在使用的共用 Shape 資源不可被誤刪。

## 10. IK 啟用後批次重新定向持續下墜

- 角色設定 IK 後執行「批次重新定向」，目前會在動畫處理過程中持續向下掉落。
- 重新定向時必須維持 Root 的高度與位移基準，避免 IK 控制骨、骨尾位置或約束結果被逐幀重複累加到 Root／角色物件位移。
- 批次流程中的每個動畫片段都應由一致的初始姿勢與 Root 基準開始，不可承接上一片段結束時的下墜偏移。
- 修正時需同時檢查有腳部 IK、手部 IK、兩者皆有，以及未設定 IK 的角色，避免為 IK 修正而改壞既有重新定向結果。

### 驗收

- 有腳部 IK 的角色批次重新定向多個動畫後，不會隨時間或片段數量持續下降。
- Root Motion 開啟與關閉時，各自保留既定行為；IK 不會額外改變角色的垂直基準。
- 單一重新定向與批次重新定向對同一動畫產生一致的 Root 高度及角色位置。
- 連續處理多個片段時，後續片段不會累積前一片段的垂直位移或 IK 約束狀態。

## 11. IK 控制骨形狀即時預覽與外觀設定

- IK 設定中的「大小」數值調整時，必須立即同步更新 3D Viewport 內對應控制骨／Custom Shape 的顯示尺寸，不需要先按 `OK` 才看到結果。
- 選擇 `Box Wireframe` 等線框樣式時，新增的 IK 控制骨必須直接使用並顯示該線框骨頭形狀；不可仍顯示一般八面體骨頭，也不可只有下拉選項改變而畫面沒有視覺效果。
- 除了「大小」，IK 外觀設定需增加：
  - 線框粗細。
  - 顏色。
- 大小、線框粗細與顏色都要在調整時即時反映於畫面中的對應控制骨。
- 新增或更新 IK 控制骨時，`Scale to Bone Length` 必須預設關閉且不得自動勾選，避免控制形狀尺寸再次受到骨架長度乘算影響。
- 按 `Cancel` 時還原進入 IK 設定前的大小、線框粗細、顏色、形狀與 `Scale to Bone Length` 狀態；按 `OK` 後才正式保留目前設定。

### 驗收

- 拖動或輸入「大小」後，Viewport 中的控制骨形狀當下同步放大或縮小。
- 切換球形、Box、Box Wireframe 或 Circle 時，骨頭立即改成所選 Custom Shape，且清楚可見。
- 調整線框粗細與顏色時，只影響目前設定的 IK 控制骨；配對骨是否同步需沿用既有左右同步規則。
- 新建 IK 控制骨的 `Scale to Bone Length` 為關閉狀態，改變原骨頭長度不會額外改變控制形狀尺寸。
- 關閉再開啟檔案後，已確認的形狀、大小、粗細、顏色與骨長縮放狀態都能正確保留。

## 12. 自動配骨架需保留目前預覽模式

- 在 `T-Pose` 預覽啟用時按「自動配骨架」，完成後必須繼續顯示同一個 T-Pose，不可自動切換成套用動畫後的預覽姿勢。
- 已確認目前回歸：`T-Pose 預覽 → 自動配骨架` 後，介面會把啟用狀態切到一般「預覽」按鈕，來源／Target 也不再同時維持 T-Pose；修正時需以執行前的 `preview_mode == TPOSE` 為準恢復狀態，不可依 Action 是否存在誤判為一般動畫預覽。
- 自動配骨架完成後，T-Pose 按鈕必須繼續保持啟用外觀，普通「預覽」按鈕不可被自動啟用；來源與 Target 兩套骨架都必須保持 Rest/T-Pose，讓使用者可以繼續檢查骨頭位置與縮放對位。
- 在一般動畫「預覽」啟用時按「自動配骨架」，完成後必須繼續顯示原本選取的 Action 與目前預覽幀，不可切換成 T-Pose、其他 Action 或未預覽狀態。
- 自動配骨架內含的骨架縮放對位不可破壞既有預覽狀態，也不可重複套用物件縮放、骨架縮放或姿勢矩陣，避免出現圖 3 的骨架／控制物件被拉離角色、散落到遠處或角色位置改變。
- 執行前需保存目前預覽模式、來源 Action、Target 原始 Action、目前幀、來源與 Target 的物件 Transform，以及預覽暫存姿勢；自動配骨與縮放完成後，依原模式重建預覽。
- 自動配骨架只更新映射、必要縮放與軸向資料；不得把動畫預覽產生的暫時姿勢誤存成新的 Rest Pose 或再次當作縮放計算基準。

### 驗收

- `T-Pose → 自動配骨架` 前後畫面都維持相同 T-Pose，按鈕狀態亦維持啟用。
- 自動配骨前後分別檢查來源與 Target 的主要骨頭姿勢；兩者都必須維持 T-Pose，不可只有 Target 或只有來源維持。
- 自動配骨後 UI 狀態必須是 `T-Pose=啟用`、`預覽=停用`，不可發生兩者互換。
- `動畫預覽 → 自動配骨架` 前後維持同一 Action、同一幀與相同姿勢，預覽按鈕仍為啟用狀態。
- 連續按兩次以上「自動配骨架」不會累積縮放、位移或旋轉，來源與 Target 骨架不會逐次分離。
- 取消 T-Pose／動畫預覽後，Target 回到進入預覽前的 Action、姿勢、物件 Transform 與顯示狀態。
- 在沒有任何預覽時執行自動配骨架，既有非預覽流程與結果不受影響。

## 13. 依角色前方與骨頭局部基底自動對軸向

- 「自動對軸向」的全域判斷以角色實際前方、上方與左右方向為準，不可單純執行來源 X 對 Target X、Y 對 Y、Z 對 Z。
- 例如來源角色以 `+Y` 為前方、Target 以 `+X` 為前方時，需先建立「來源前方 → Target 前方」的角色全域座標轉換。
- Root 負責套用角色全域基底轉換，包括 Root 旋轉、Root 位移、前方、上方、左右方向及必要的整體縮放。
- 除了 Root，每根已映射骨頭仍需依來源與 Target 的 Rest Pose、父子階層及 Bone Roll 計算局部基底轉換；不可假設兩套骨架的局部 X／Y／Z 軸一致。
- 不可直接把來源 Euler 單一通道的數值複製到 Target 的另一通道。來源以 `+Y` 表示右彎、Target 以 `+Z` 表示右彎時，需先將來源旋轉求值成矩陣或 Quaternion，再進行完整的換基底轉換，最後才烘焙到 Target。
- 每根骨頭的概念轉換為：`Target 旋轉 = 局部軸向轉換 × 來源旋轉 × 局部軸向轉換⁻¹`；實際實作需同時納入角色全域前方轉換與父骨空間。
- 自動流程不得直接執行破壞性的 `Recalculate Roll` 或修改來源／Target 的 Rest Pose。Bone Roll 差異應以虛擬轉換矩陣處理，保留既有蒙皮、約束與動畫。
- UI 中的「調整軸向」保留作為個別骨頭的人工例外修正；一般情況由程式自動完成每根骨頭的局部轉換。
- 當角色前方無法可靠判斷時，提供來源與 Target 的前方軸人工選項，例如 `+X`、`-X`、`+Y`、`-Y`；上方軸與左右手座標系亦須一致檢查。

### 驗收

- 來源 `+Y` 朝前、Target `+X` 朝前時，Root 位移與轉向會沿 Target 的正確前方播放，不會側走或反向。
- 來源與 Target 的對應骨頭 Bone Roll 不同時，彎曲、扭轉和左右動作仍保持相同語意，不會只因 Euler 通道不同而轉錯軸。
- 來源某動作用局部 `+Y` 右彎、Target 需以局部 `+Z` 右彎時，烘焙結果會落在 Target 的正確旋轉方向與正負號。
- 自動對軸向前後，來源與 Target 的 Rest Pose、Bone Roll、蒙皮及既有 Action 資料不被修改。
- 僅調整 Root 時不足以修正局部骨軸差異的案例，仍能透過逐骨 Rest 基底轉換得到正確姿勢。
- 同一來源動畫重複重新定向，輸出結果一致，不累積軸向偏移或重複換軸。

## 14. 自動配骨架的縮放需套用到實際骨架

- 「自動配骨架」計算出的骨架縮放對位不可只寫入預覽 Pose、暫存矩陣、顯示倍率或其他僅在目前模式生效的狀態。
- 完成自動配骨後，對位縮放需真正套用到實際參與映射的 Armature，使 Object Mode、Pose Mode 與 Edit Mode 顯示相同的骨架尺寸。
- 目前切換到 Edit Mode 時會回到縮放前的原始大小，表示縮放只影響 Pose／預覽顯示；後續需消除此模式差異。
- 套用實際骨架縮放時，需同步處理相關 Mesh、Armature Modifier、父子關係、控制骨、約束及既有物件 Transform，避免角色網格與骨架分離或再次被重複縮放。
- 自動配骨重複執行時，應以已套用後的實際尺寸判斷，不可每次再次乘上相同比例。
- T-Pose 與動畫預覽只負責姿勢顯示；離開預覽、切換模式或重新開啟檔案後，已確認的骨架對位尺寸都必須保留。

### 驗收

- 自動配骨完成後，在 Object、Pose、Edit Mode 之間切換，來源與 Target 骨架的相對尺寸保持一致。
- 進入 Edit Mode 不會突然顯示縮放前的骨架大小。
- 取消 T-Pose 或動畫預覽後，骨架仍保留自動配骨所套用的實際尺寸。
- 儲存並重新開啟 `.blend` 後，骨架、網格及控制骨仍維持正確對位。
- 連續執行兩次自動配骨不會產生二次縮放，網格、骨架、約束和 IK 控制骨不會分離。

## 15. 動畫預覽需同步顯示來源與 Target 骨架

- 按下「預覽」後，來源骨架與 Target 骨架都必須顯示目前選取動畫的動作，不可只有其中一套骨架播放、另一套停在 Rest Pose、T-Pose 或舊姿勢。
- 來源骨架播放原始 Action；Target 骨架同步顯示依目前骨骼映射、全域前方、逐骨局部軸向、縮放、Root 與 IK 設定換算後的預覽結果。
- 兩套骨架需共用播放／暫停、時間軸拖曳與目前幀。若來源與 Target 的幀起點不同，需以片段內的相對時間對齊，不可產生固定幀偏移。
- 預覽期間修改映射、軸向、IK 或縮放設定時，Target 預覽應更新為目前設定的結果；來源仍維持原始動作，方便直接比較差異。
- 進入預覽前需分別保存來源與 Target 的 Action、Action Slot、NLA 狀態、目前幀、姿勢及顯示狀態；取消預覽時完整還原，不得在 Target 留下暫存 Action。
- 若 Target 原本沒有 Action，離開預覽後必須恢復為 `None`。

### 驗收

- 按下「預覽」後，可同時看到來源與 Target 在相同時間點做出對應動作。
- 播放、暫停或拖曳時間軸時，兩套骨架同步更新，不會有一套停住或延遲一幀。
- 來源顯示原始動畫，Target 顯示重新定向預覽；兩者不會誤用同一個不相容的 Action Slot。
- 預覽中調整映射或軸向後，Target 更新而來源原始動作不被修改。
- 關閉預覽後，兩套骨架各自恢復進入預覽前的 Action、姿勢、幀與顯示狀態。

## 16. 全部重設需清除 IK 線框形狀資料

- 按下「全部重設」時，目前建立的 IK 設定雖被重設，但 Outliner 仍殘留 `__FBR_IK_Shapes__` 集合、`FBR_IK_SHAPE_BOX` 等線框物件及其 Mesh 資料。
- 全部重設需一併解除控制骨的 Custom Shape 引用，並清除此外掛建立且已不再使用的 IK 形狀物件、Mesh 與專用集合。
- 僅能刪除 Faidlix Bone Remap 自己建立的形狀資料；不可誤刪使用者物件或仍被其他 IK 控制骨引用的資料。
- 若仍有任何 IK 設定正在使用同一個共用形狀，必須保留該形狀，直到最後一個引用被移除。

### 驗收

- 建立 IK 線框形狀後按「全部重設」，Outliner 不再顯示空的 `__FBR_IK_Shapes__` 集合。
- `FBR_IK_SHAPE_*` 物件與對應 Mesh 在沒有使用者後會完整移除，不留下孤立資料塊。
- 重複建立 IK、全部重設、再建立 IK，不會累積 `.001`、`.002` 等重複形狀物件。
- 使用者自行建立的物件、Mesh、集合及非本外掛的 Custom Shape 不受影響。

## 17. 首次動畫預覽不可把來源骨架縮得極小

- 已確認目前回歸：第一次按一般「預覽」時，來源骨架會突然縮得非常小；案例中的來源 Armature Scale 被改成約 `(0.000049, 0.000049, 0.000049)`。
- 此時第一次執行「自動配骨架」仍未恢復正確尺寸，必須再按第二次「自動配骨架」，來源骨架才會變回正常大小；顯示目前縮放計算／套用順序依賴前一次執行留下的狀態。
- 但第二次執行又會造成另一個錯誤：Target 骨架被移動到很高／很遠的位置，案例中的 Target Location Y 約為 `200.07 m`，旋轉座標也不再是原本的對位狀態。
- 自動配骨與預覽流程不得把來源 Root／物件位置、動畫中的 Root Motion、預覽用對齊矩陣或縮放後座標回寫到 Target 的 Object Transform。
- 來源骨架的尺寸修正與 Target 的位置／旋轉必須分開處理；不可為了讓來源恢復正常尺寸而再次累乘或覆寫 Target `matrix_world`。
- 圖 1 為第二次自動對位後的一般動畫預覽；此時畫面上的尺寸看似已被修正，但只是目前預覽狀態。
- 圖 2 為之後切換到 `T-Pose` 預覽的結果：來源骨架再次變回超大尺寸，且仍維持匯入時躺倒的方向。這表示自動縮放與朝向對位沒有持久記錄到來源 Armature 的實際 Transform／骨架基準，而是在切換預覽模式時被原始矩陣覆蓋。
- 一般動畫預覽與 T-Pose 預覽必須共用同一份已確認的來源實際縮放及朝向基準；切換模式只能更換 Pose／Action，不得切換回匯入前的物件矩陣。
- 自動配骨後需明確保存「匯入原始 Transform」與「已確認對位 Transform」兩種狀態；正常預覽使用已確認對位 Transform，只有執行取消／全部重設時才能恢復原始 Transform。
- 修正後第一次「自動配骨架」就必須得到最終正確尺寸，不可要求使用者按第二次來修正第一次的結果。
- 預覽只能套用已確認的骨架對位結果，不可再次把匯入單位換算、FBX 縮放、`_fbr_alignment_scale` 或自動配骨比例乘到來源物件 Scale。
- 開始預覽前需保存來源 Armature 的完整 `matrix_world`／Transform；建立預覽 Action 與對齊顯示時，不得覆寫實際骨架的持久縮放。
- 若骨架已由「自動配骨架」完成實際縮放，預覽應直接使用目前尺寸，不能再把相同比例套用第二次。
- 第一次與後續重複開關預覽必須得到相同尺寸，不可逐次累積縮放。

### 驗收

- 匯入來源並完成自動配骨後，記錄來源 Armature 的 `matrix_world`、Scale 與世界尺寸；第一次按「預覽」前後保持一致。
- 從全新匯入狀態執行一次「自動配骨架」後，尺寸必須立即正確；第二次執行應為冪等操作，尺寸與第一次完成後完全相同。
- 記錄 Target 執行前的 Location、Rotation、Scale 與 `matrix_world`；第一次及第二次「自動配骨架」後都不得出現未要求的物件位移或旋轉。
- 預覽 Action 含 Root Motion 時，重複自動配骨也不可把動畫幀中的 Root 位移寫入 Target Object Location。
- 第二次自動對位完成後，在一般動畫預覽與 T-Pose 預覽之間反覆切換，來源骨架的世界尺寸、站立方向與對位位置都必須一致。
- T-Pose 預覽需驗證來源骨架不會恢復為匯入時的超大尺寸或躺倒方向，並且來源／Target 仍保持可直接比較的對位狀態。
- 儲存並重新開啟 `.blend` 後再進入 T-Pose，仍應使用已確認的來源縮放與朝向，證明對位狀態不是只存在於暫時預覽快照。
- 連續開啟／關閉預覽至少三次，來源骨架尺寸不變且不會逐次縮小。
- 來源與 Target 都能播放目前動作，但預覽不會改寫兩者的持久 Object Transform。
- 取消預覽後，來源與 Target 的 Transform、Action、Action Slot 與顯示狀態完整還原。

## 18. 複數動畫子列的動畫名稱需左移

- 複數動畫檔展開後，子動畫列的「動畫名稱」目前向右縮排過多，檔案名稱欄下方留下大片空白，導致後面的「時間」欄被壓縮而顯示不完整。
- 子動畫名稱需左移到畫面黃框所示的空白區；只保留辨識父檔／子動畫階層所需的最小縮排，不可沿用父檔案名稱欄的完整寬度作為空白。
- 欄位標題與資料列需維持相同欄線：啟用、檔案名稱、動畫名稱、時間、設為原地動畫、複製對稱動畫。
- 父檔列仍顯示檔案名稱與動畫數量；子動畫列不必保留一整個空白檔案名稱欄，應把可用空間分配給動畫名稱與時間。

### 驗收

- 展開含多個 Action 的 `.blend` 後，子動畫名稱從黃框位置開始顯示，不再出現過寬空白縮排。
- 一般側邊欄寬度下，動畫名稱與時間可同時辨識；時間不因無用途的縮排而被截斷。
- 收合／展開父檔不會改變各欄寬度或讓標題與內容錯位。
- 單一動畫檔與複數動畫檔使用一致的時間欄位置，右側 O／X 操作欄仍保持對齊。

## 19. 動畫清單欄位寬度可由使用者調整

- 上方欄位標題「啟用、檔案名稱、動畫名稱、時間、設為原地動畫、複製對稱動畫」需提供可拖曳的欄寬調整。
- 使用者拖曳任一欄位分隔位置時，下方所有父檔列與子動畫列的對應欄位需同步改變寬度，不可只移動標題文字。
- 欄寬狀態需由同一組比例／寬度資料驅動標題與內容，避免展開、收合或捲動後重新錯位。
- 各欄需設定合理最小寬度；不可把啟用勾選框、O／X 按鈕或時間欄縮到完全無法操作或辨識。
- 側邊欄整體寬度改變時，保留使用者設定的相對配置；超出空間時依最小寬度處理，不可互相覆蓋。
- 欄寬設定應保留於目前 Blender 工作階段；是否跨檔案／重開 Blender 保存，正式實作時優先採外掛偏好或 Scene 屬性中較不干擾檔案資料的方式。

### 驗收

- 拖曳「動畫名稱／時間」分隔位置後，標題、父檔列與全部子動畫列同步移動。
- 展開或收合複數動畫、上下捲動清單後，使用者設定的欄寬不會重設。
- 調整側邊欄寬度後，各欄仍依設定排列且不重疊；必要時文字截斷但操作按鈕保持可用。
- 新增或刪除動畫檔案後，新列立即沿用目前欄寬。

### 骨骼對應清單

- 相同的可調欄寬規則也適用於「骨骼對應」清單，包括來源骨骼、Target 骨骼、IK 設定、軸向 O／X 狀態與調整軸向按鈕所在欄位。
- 拖曳標題分隔位置時，普通骨頭列、手指／腳趾縮排列、目前選取列，以及展開中的軸向或 IK 設定內容都需使用同一組欄寬。
- IK 設定與軸向設定展開區不可自行改變主清單總寬度或把右側欄位推離可視區；展開內容應在目前清單寬度內重新配置。
- 來源與 Target 骨頭名稱欄可由使用者加寬以辨識長名稱；IK、O／X 與調整軸向欄需保留可操作的最小寬度。

### 骨骼對應驗收

- 調整來源或 Target 骨骼欄寬後，所有骨頭列及標題同步對齊。
- 收合／展開手指、腳趾、IK 或軸向設定後，欄寬與目前捲動位置都不會重設。
- 長骨頭名稱加寬後可顯示更多內容，右側 IK 與軸向操作仍保持可見且可點擊。

## 20. IK 線框顯示方式、UI 與腳部位置

### Custom Shape 顯示

- 按下「設定 IK」後，不要把 `FBR_IK_SHAPE_BOX` 等形狀來源物件以實際物件尺寸顯示在場景中；圖 1 的巨大方框不應出現在角色周圍。
- 形狀來源物件及 `__FBR_IK_Shapes__` 集合應保持隱藏，只由 IK 控制骨的 Custom Shape 引用來顯示線框。
- IK 控制骨的 `Scale to Bone Length` 必須保持不勾選，避免控制形狀再受骨頭長度放大。
- IK 控制骨的 `Wireframe` 必須勾選，使 Custom Shape 直接以線框呈現，而不是顯示實體表面。
- 隱藏形狀來源物件不得影響控制骨 Custom Shape 的可見性；控制骨上仍要看到正確大小、顏色與線寬的線框。

### IK 設定 UI

- `Width`／線框粗細控制項需直接放在 IK 設定列的「大小」數值後面，與形狀、大小位於同一列。
- 大小只控制控制骨上的 Custom Shape 顯示尺寸，不可改變形狀來源物件的場景 Transform，也不可把來源物件取消隱藏。
- IK 顯示「大小」允許的最小值為 `0.01`；輸入、拖曳或程式設定都不可低於此值。
- Width 即時控制 Pose Bone 的 Custom Shape Wire Width；調整時控制骨上的線框立即更新。

### 腳部 IK 位置

- 已確認目前回歸：腳骨設定 IK 後執行批次重新定向，建立出的 IK 方框不在腳部，而是漂浮在角色旁邊或遠離腳底。
- IK 控制骨建立時需將來源腳骨位置正確轉換到 Target Armature／Pose 空間；不可直接混用世界空間、來源 Armature 空間與 Target Bone 局部空間座標。
- 初始控制骨位置應對齊所設定 Target 腳骨的預期控制點；左右腳需各自對齊自己的腳骨，不能沿用另一側或建立形狀來源物件的原點。
- 批次烘焙每一幀時，IK 控制骨位置需追蹤重新定向後的腳部目標；不可只在建立當下定位一次後留在固定世界座標。
- 骨架縮放、前方軸向轉換與 Root Motion 都需納入 IK 位置換算，但不得重複套用縮放或 Object Transform。

### 驗收

- 設定 IK 後，場景中只看到控制骨上的線框，不會看到形狀來源物件形成的巨大方框。
- 檢查控制骨屬性時，`Scale to Bone Length` 為關閉、`Wireframe` 為啟用。
- IK UI 第一列依序包含形狀、大小與 Width，調整大小／Width 可即時看到控制骨線框變化。
- 將大小設為 `0.01` 時仍可正常顯示與保存；嘗試輸入更小數值時會限制為 `0.01`。
- 左右腳設定 IK 並批次重定向後，各控制框中心位於對應腳部，不會漂浮在角色旁邊。
- 在動畫首幀、中間幀與末幀檢查，IK 控制骨都跟隨腳部位置，且 Root 不會因此持續下墜。
- 一般預覽、T-Pose、批次輸出及重新開啟檔案後，形狀來源物件仍保持隱藏。
